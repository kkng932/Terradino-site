연구 기록 02

아키텍처

VContainer 부모-자식 Scope

문제

씬 전환 시 싱글톤 초기화 순서가 꼬여 데이터 매니저에서 null 참조가 발생했습니다. Init 씬에서 미리 초기화해 해결했지만, 특정 씬에서만 쓰는 매니저까지 메모리에 계속 남았습니다.

해결

전역 시스템은 Root Scope인 ProjectLifetimeScope에, 씬 전용 시스템은 각 씬의 자식 Scope에 등록했습니다. 씬 전용 매니저는 이제 씬과 함께 생성되고 해제됩니다.

광고 SDK 추상화 · IAdService

문제

이전 프로젝트에서 AdMob을 Unity Ads로 교체할 때, 싱글톤으로 직접 참조하던 광고 코드가 곳곳에 흩어져 있어 모두 고쳐야 했습니다.

해결

광고 SDK를 IAdService 인터페이스로 추상화해 컨테이너에 등록했습니다. 광고 플랫폼을 바꿔도 사용하는 쪽 코드는 그대로 두고 등록부만 수정하면 됩니다.

제네릭 IEventBus

문제

이전 프로젝트의 업적 시스템은 object 기반 이벤트 버스였습니다. 이번에는 알 터치 업적처럼 호출 빈도가 훨씬 높아, 박싱/언박싱으로 인한 GC 스파이크가 우려됐습니다.

해결

제네릭 기반 IEventBus로 바꿔 값 타입 이벤트를 박싱 없이 전달하도록 했습니다.

연구 기록 04

자동화 툴

스프레드시트 → ScriptableObject

문제

이전 프로젝트에서는 데이터 필드가 추가·수정될 때마다 파싱 코드를 직접 고쳐야 했고, 필드가 늘수록 관리 포인트도 함께 늘었습니다.

해결

C# Reflection으로 구글 스프레드시트를 ScriptableObject로 자동 변환하는 툴을 만들었습니다. 필드가 늘어도 파싱 코드는 고치지 않고, 메뉴 한 번으로 모든 테이블을 갱신합니다.

Sheets→TSV Fetch→Reflection 파싱→ScriptableObject
블로그: 스프레드시트 변환 툴 →

공룡 파츠 Sprite Tool

문제

수백 개의 공룡 파츠를 손으로 세팅하다 보니 본 정보나 명명 규칙을 한두 개씩 틀렸고, 시간도 오래 걸렸습니다.

해결

임포트 설정, 명명 규칙에 따른 정리, Sprite Library 할당을 에디터 툴로 자동화했습니다. 같은 파츠의 색 변형에는 리깅 정보(본 이름·위치·회전)를 버튼 한 번으로 복사해, 반복 작업을 90% 이상 줄였습니다.
